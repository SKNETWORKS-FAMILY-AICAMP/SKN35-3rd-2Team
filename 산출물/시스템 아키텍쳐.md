## 1. 문서 개요

### 1.1 목적 및 배경

본 문서는 **LangChain, LangGraph, MCP(Model Context Protocol)** 프레임워크를 기반으로 개발자를 위한 지능형 기술 질의응답 및 트러블슈팅 서비스를 제공하는 시스템의 전체 소프트웨어/데이터 아키텍처를 정의한다. 복합 개발 질의에 대응하기 위해 단순 검색을 넘어선 **모듈러 RAG (Modular RAG)**, **MCP 기반 외부 도구 연동**, **멀티모달 비전 분석**을 결합한 통합 멀티 에이전트 오케스트레이션 시스템의 청사진을 제시한다.

### 1.2 시스템 범위 및 핵심 기능

- **Supervisor 기반 Multi-Agent 오케스트레이션**: 중앙 오케스트레이터가 질의 의도와 이전 수집 결과를 바탕으로 작업 경로를 동적으로 분기 및 순환 제어.
- **모듈러 RAG (Modular RAG) 파이프라인**: 전처리(질의 재작성/확장), 검색(하이브리드), 후처리(RRF 융합/CrossEncoder 재정렬), 조건부 자가 피드백 루프(Adaptive Retry), 문맥 압축(Compressor)을 독립 모듈로 조합한 고도화 아키텍처.
- **MCP 표준 도구 연동 (Self-Correction)**: Stdio IPC 통신 기반 외부 도구(PyPI 실시간 버전, GitHub 이슈 검색, 파이썬 심볼 검증) 호출 및 자가 오류 복구 루프.
- **Multimodal 에러/코드 이미지 서브그래프**: 첨부 이미지(최대 3장)를 `validate → resize → encode → read → build_analysis` 5개 노드로 처리(무결성 검증, 리사이징, 비전 추론, 비밀값 마스킹). 읽은 내용은 질문에 합류시켜 이후 RAG 검색과 MCP 도구 선택에 쓰고, 이미지 원본은 서버 디스크에 파일로 저장한다.
- **엔터프라이즈 영속성 & 세션 관리**: RDBMS(MySQL/TiDB Cloud) 기반 계정/대화 이력/출처 관리, 이미지 파일 저장(DB에는 경로만), Pinecone 벡터 데이터베이스 기반 문서 검색.
- **실시간 응답 경험**: 답변 토큰 스트리밍과 처리 단계(Supervisor, RAG, MCP, MULTI_MODAL, ANSWER) 표시(`src/graph/progress.py`).

## 4. 모듈러 RAG (Modular RAG) 심층 아키텍처

### 4.1 왜 본 시스템은 "모듈러 RAG (Modular RAG)"인가?

본 프로젝트의 검색 파이프라인은 단순 Advanced RAG 수준을 넘어 학계 및 업계에서 정의하는 **모듈러 RAG (Modular RAG)** 아키텍처 표준을 만족한다.

#### 📊 RAG 세대별 패러다임 비교

| 구분                | 나이브 RAG (Naive RAG)   | 어드밴스드 RAG (Advanced RAG)      | 본 프로젝트의 모듈러 RAG (Modular RAG)                |
| :------------------ | :----------------------- | :--------------------------------- | :---------------------------------------------------- |
| **아키텍처 형태**   | 선형 파이프라인 (Linear) | 고정된 전/후처리 파이프라인        | **독립 모듈형 그래프 (DAG & State Machine)**          |
| **모듈 독립성**     | 결합도 높음 (일체형)     | 전처리/후처리 단계가 하드코딩 결합 | **각 단계가 LangGraph Node로 완벽히 모듈화**          |
| **흐름 제어**       | 단방향 고정 흐름         | 단방향 분기 없음                   | **동적 라우팅 및 조건부 재시도 피드백 루프**          |
| **검색 방식**       | 단순 Dense 벡터 검색     | 단순 하이브리드 검색               | **Multi-Query + Hybrid + RRF 랭킹 융합**              |
| **품질 검증**       | 결과 검증 없음           | 정적 상위 N개 선별                 | **CrossEncoder 점수 검증 + 점수 미달 시 재작성 루프** |
| **컨텍스트 최적화** | Chunk 원문 단순 결합     | 기본 필터링                        | **Context Compressor를 통한 능동적 노이즈 압축**      |

#### 🧩 본 시스템의 6대 모듈러 RAG 구성 모듈

1. **Pre-Retrieval Module (`query_rewrite`, `multi_query`)**: 사용자 질의를 독립 검색 쿼리로 정제하고 3개의 다각도 파생 쿼리를 생성하여 검색 재현율(Recall) 극대화.
2. **Retrieval Module (`retriever`)**: Pinecone Vector DB에서 Dense 임베딩 유사도와 Sparse 키워드 매칭(BM25)을 결합한 하이브리드 인덱스 탐색(가중치 alpha 0.7, 검색어마다 후보 20개).
3. **Post-Retrieval Fusion Module (`rrf`)**: 다중 질의에서 수집된 청크들의 순위를 Reciprocal Rank Fusion 공식($RRF\_Score = \sum \frac{1}{k + rank}$)으로 통합.
4. **Post-Retrieval Verification Module (`rerank`)**: CrossEncoder(BAAI/bge-reranker-v2-m3, 로컬 실행)를 사용해 질문과 문서 간의 의미론적 유사도 점수를 $0.0 \sim 1.0$으로 정밀 채점.
5. **Adaptive Feedback Loop (`route_after_rerank`, `retry_counter`, `clear_documents`)**: 최고 점수가 임계치(0.5) 미만일 경우 최대 2회까지 `query_rewrite` 노드로 역행하여 질문을 다듬고 재검색하는 자가 학습형 루프 구비. 재시도를 모두 쓰고도 미달이면 `clear_documents`가 검색 문서를 비우고 종료하여, 점수가 낮은 문서가 답변에 전달되지 않게 한다.
6. **Context Processing Module (`filter_documents_by_score`, `context_compressor`)**: 재정렬 점수가 낮은 문서를 먼저 제외하고, 남은 문서 청크 중 핵심 문맥만을 선별 압축하여 LLM 프롬프트에 주입할 최적의 `context` 생성.

## 5. MCP 및 멀티모달 서브시스템 아키텍처

### 5.1 MCP (Model Context Protocol) 자가 치유(Self-Correcting) 파이프라인

- **독립 Stdio 서버 프로세스**: `src/mcp_integration/server/server.py`가 앱과 IPC 통신으로 격리 실행되어 메인 앱의 안정성 보장.
- **등록된 엔지니어링 도구 모음**:
  - `version_tools`: `get_latest_version`(PyPI 실시간 최신 버전, 출시일), `check_version_compat`(패키지 간 호환성 검증 계산).
  - `github_tools`: `search_github_issues`, `get_github_issue` (LangChain/LangGraph/MCP 공식 저장소 Issue/PR 검색 및 본문 파싱).
  - `symbol_tools`: `check_symbol_exists`(설치된 라이브러리 내 함수/클래스/모듈의 실존 여부 검증, Hallucination 방지).
- **연결 재사용과 인젝션 방어**: 서버 연결을 `pool.py`로 재사용하고, 도구가 가져온 글은 "외부 데이터"로 표시해 그 안의 지시문을 따르지 않도록 한다(프롬프트 인젝션 방어).
- **자가 치유 루프**: 도구 이름 오타, 필수 파라미터 누락, 호출 실패 발생 시 LLM에게 에러 메시지를 컨텍스트로 전달하여 최대 2회까지 올바른 도구/인자를 다시 선택(`select_tool`)하도록 유도.

### 5.2 Multimodal Vision 분석 서브그래프

- **5개 노드 서브그래프**: `validate_images → resize_images → encode_images → read_images → build_analysis` (`src/agent/multi_modal_agent.py`). 읽을 이미지가 없거나 변환이 실패하면 `build_analysis`로 바로 이동하며, 어떤 단계가 실패해도 예외를 던지지 않고 실패 안내가 `image_analysis`에 담긴다.
- **무결성 및 용량 검사**: 파일 앞부분 바이트로 형식(PNG, JPEG, WEBP)을 판별하고, 한 메시지에 최대 3장, 한 장 2MB 한도를 적용한다. 긴 변이 2048을 넘으면 비율을 유지하며 축소한다.
- **격리된 시각 정보 추출**: 이미지 바이트와 Base64는 서브그래프 안에서만 오가고, 메인 State에는 텍스트화된 `image_analysis` 결과만 전달하여 토큰 비용과 지연 시간을 절감.
- **읽은 내용을 질문에 합류**: 읽기에 성공하면 읽은 내용을 `original_question` 뒤에 붙여, 이미지만 올린 질문이어도 이후 RAG 검색어와 MCP 도구 선택이 실제 오류 문구를 쓰게 한다.
- **이미지 원본 저장**: 원본과 썸네일은 서버 디스크 파일로 저장하고 DB에는 경로만 둔다(`src/db/storage.py`).

## 9. 비기능 아키텍처 및 품질/안정성 설계

### 9.1 결함 허용 및 Graceful Degradation (오류 방어)

- **외부 의존성 격리**: MCP 서버 비정상 종료, 외부 API 타임아웃, Pinecone 벡터 검색 실패 등의 예외 발생 시 그래프 전체 중단을 차단.
- **대체 응답 제공**: 수집 실패 정보를 `failed_record`로 포장하여 Answer Agent로 인계, "실시간 조회가 원활하지 않으나 기본 학습 지식을 기반으로 안내합니다" 형태로 서비스 연속성 유지.

### 9.2 보안 및 민감 정보 보호 (Data Security & Masking)

- **비밀값 자동 마스킹 (`mask_secrets`)**: DB 저장 및 로깅 직전, OpenAI Key(`sk-...`), NVIDIA Key(`nvapi-...`), DB 패스워드 등 민감 정보를 정규식으로 감지하여 `[MASKED:...]`로 자동 치환.
- **소유권 검증 (Ownership Enforcement)**: 모든 대화 이력과 첨부파일 조회 시 `user_id`를 강제 검증하여 타인 데이터 무단 열람 원천 차단.
- **이미지 파일 접근 방어**: 파일 이름은 사용자가 준 이름이 아니라 번호와 해시로 만들고, 저장 폴더 밖으로 나가는 경로는 읽기와 쓰기 모두 거절한다. 파일은 소유자를 확인하는 DB 함수를 거쳐서만 읽는다.
- **프롬프트 인젝션 방어**: MCP 도구 결과와 검색 문서처럼 외부에서 가져온 글은 "데이터"로 표시하고, 답변 프롬프트가 그 안의 명령이나 링크 안내 요구를 따르지 않도록 규정한다.

### 9.3 비용 및 자원 최적화 (Resource Optimization)

- **대화 이력 상한 관리 (`limits.py`)**: `HISTORY_MAX_TURNS` 및 `HISTORY_MAX_TOKENS` 상한 정책을 통해 무분별한 토큰 누적 방지.
- **이미지 데이터 경량화**: 이미지는 읽기 단계에서 모델을 한 번만 호출하고 이후에는 텍스트(`image_analysis`)만 사용한다. Supervisor 라우팅 시 수 MB에 달하는 원본 이미지 바이트 대신 메타데이터(`image_summary`)만 전달하여 호출 지연 시간과 비용을 90% 이상 절감.
