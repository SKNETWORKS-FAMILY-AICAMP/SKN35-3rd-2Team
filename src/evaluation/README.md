# UI 연결 및 평가 작업

## 담당 범위

수정 범위는 `main.py`, `src/app/**`, `src/evaluation/**`입니다.
그 외 파일은 읽기만 합니다. 수정이 필요하면 팀원 동의를 위한 제안을 먼저 합니다.
커밋 전 담당 밖 파일 포함 여부를 확인해 사용자에게 알립니다.
작업 후 변경 목적, 사용법, 검증과 한계를 팀원에게 설명합니다.

## 남긴 코드

- `main.py`: 기존 dev의 Streamlit 실행 진입점을 유지합니다.
- `src/app/chat.py`: 질문 입력, 대화 표시, 초기화, 모드 전환, 오류 안내.
- `src/app/chat_service.py`: 기존 `workflow()`를 호출하는 UI 어댑터입니다.

- `test_chat_connection.py`: UI 및 기존 그래프 연결을 모의 모델로 검증합니다.

## 실행

프로젝트 가상환경을 활성화한 뒤 프로젝트 루트에서 실행합니다.

```powershell
python -m streamlit run main.py
python -m pytest src/evaluation/test_chat_connection.py -q -p no:cacheprovider
```

OpenAI 모드는 `OPEN_MODEL`과 팀 모델 생성 함수 설정을 사용합니다.
연습 모드는 API 호출 없이 화면을 확인합니다. NVIDIA 직접 호출 모드도 유지합니다.
DB 연결에서는 현재 질문을 먼저 저장하고, 상한이 적용된 DB 이력을 전달합니다.
thread_id는 DB의 conversation_id를 문자열로 사용합니다.
dev 체크포인터는 유지하되 요청마다 그래프를 새로 만들어 같은 이력을 중복 누적하지 않습니다.
로그인 전 시험 화면은 기존 세션 이력과 임시 ID를 사용합니다.
모델·검색·DB·라우팅 내부 구현은 추가하지 않았습니다.

## 현재 한계 및 팀원에게 확인할 내용

- 일반 질문 그래프만 연결했습니다. RAG·MCP·이미지는 준비 중 안내를 표시합니다.
- dev 그래프가 미구현 경로를 선택하면 조건 분기의 KeyError를 UI에서 준비 중으로 변환합니다.
  이 처리는 현재 dev 계약에 한정되며, 담당자가 오류·결과 계약을 제공하면 그 계약에 맞춰 바꿉니다.
- Supervisor는 dev 그대로 마지막 메시지만 판단합니다. 후속 질문의 라우팅 문맥 개선은 담당자와 조율합니다.
- dev 노드의 모델 생성 위치와 타임아웃을 유지합니다. UI에서 타임아웃을 새로 강제하지 않습니다.
- 로그인 화면·이미지 분석·출처 추출은 이번 작업에 포함하지 않습니다. DB 저장 연결 함수는 아래 합의대로 준비했습니다.
- 자동 테스트는 외부 API를 호출하지 않습니다. 실제 답변 품질은 새 코드에서 재평가해야 합니다.
- 어제 RAG 기록과 22개 테스트 결과는 취소한 실험 구현의 과거 기록이며 현재 코드 결과가 아닙니다.

## 오류 해결 중심 평가 개정

파이썬 개념 질문을 ERR01~ERR10 오류 진단 질문으로 교체했습니다. 이전 E ID를 재사용하지 않습니다.
429 속도 제한과 사용 한도, 인증, 시간 초과, 벡터 차원, 프롬프트 변수, 그래프 반복, 도구 메시지 오류를 다룹니다.
문맥 CTX01~CTX02, 기능 연결 후 EXT01~EXT04는 별도로 기록합니다.
원인 진단·해결 가능성·설명 이해도·환각 방지·문서 근거를 평가하고 핵심 실패를 따로 적습니다.
질문표 변경만 했으며 새 ERR 질문의 실제 AI 답변은 아직 평가하지 않았습니다.

## 대상 사용자와 MCP 평가 추가

대상은 LLM·RAG를 개발하거나 LangChain·LangGraph·MCP를 학습하는 개발자입니다.
초보자도 이해할 수 있는 설명은 평가 기준으로 유지합니다.
MCP01~MCP06을 추가했습니다: stdio 연결 종료, stdout 파싱 실패, 메서드 오류,
요청 인자 오류, 초기화 시간 초과, 도구 실행 실패.
핵심 평가는 LangChain·LangGraph·MCP이고 OpenAI·Pinecone 오류는 보조 사례입니다.
MCP 오류에 대한 텍스트 진단과 도우미 자체의 MCP 외부 호출 테스트를 구분합니다.
SDK·프로토콜 버전과 전송 방식을 기록하며, 명시한 구버전 규격을 최신 버전 전체로 일반화하지 않습니다.
평가 문서만 변경했습니다. MCP 서버·클라이언트 및 그래프 구현은 수정하지 않았습니다.
추가 질문은 아직 실제 답변 품질을 평가하지 않았습니다.

## 팀원 확인 후 DB 이력 연결

- 합의: thread_id는 DB 대화 ID, 답변 문맥은 매번 DB의 제한된 이력으로 전달합니다.
- `run_db_chat(question, user_id=..., conversation_id=...)`: 질문 저장 → 제한된 이력 조회 → 새 그래프 호출 → 성공 답변 저장.
- 새 채팅에서는 conversation_id를 생략합니다. 반환된 conversation_id를 다음 질문에서 사용합니다.
- DB 이력에 현재 질문이 이미 있으므로 추가하지 않습니다. DB가 마스킹·길이 제한한 내용을 그대로 사용합니다.
- 실패한 질문은 DB에 남고, 오류 안내는 답변으로 저장하지 않습니다.
- future 로그인 UI는 검증된 사용자 ID를 session_state.user_id에 넣고, 대화 선택 시 conversation_id를 설정합니다.
- 현재 로그인 화면은 추가하지 않았습니다. 사용자 ID가 없으면 기존 시험 화면을 사용합니다.
- 대화 초기화·모드 변경은 conversation_id를 비웁니다. 기존 DB 대화를 삭제하지 않습니다.
- DB 함수와 그래프 내부는 수정하지 않았습니다.
- 검증: `python -m pytest src/evaluation/test_chat_connection.py src/evaluation/test_db_chat_connection.py -q -p no:cacheprovider`.
- DB 연결 테스트는 메모리 SQLite만 사용합니다. 공유 DB와 실제 API에 접속하지 않습니다.
